# RSM Design System — AI Agent Guide

This document is the canonical reference for design and UI work in this repo. Read it before adding any new component, screen, or styling.

## 1. Position

The prototype now leans **directly on the WordPress design system** packages that ship in `node_modules`:

- **`@wordpress/theme/design-tokens.css`** — single source of truth for `--wpds-*` design tokens. Imported once in [src/main.jsx](../main.jsx), so the tokens are available globally on `:root`.
- **`@wordpress/ui`** — content/layout primitives validated for production use (Badge, Card, Collapsible, CollapsibleCard, EmptyState, Link, Stack, Text, VisuallyHidden).
- **`@wordpress/components`** — interactive controls (Button, TextControl, SelectControl, RangeControl, ColorPicker, FontSizePicker, Dropdown, DropdownMenu, Modal, Popover, Tabs, ToggleGroupControl, SearchControl, CheckboxControl, ToggleControl, PanelBody, `__experimentalNumberControl`, `__experimentalUnitControl`, `__experimentalBoxControl`, …).
- **`@wordpress/icons`** — icon glyphs.

There is **no locally-authored primitive layer**. The earlier `src/design-system/primitives/` folder ([PR #9](https://github.com/getdave/rsm-editor-prototype/pull/9)) and its `--wpds-*` token files have been retired in favor of the official packages.

## 2. Where tokens come from

The authoritative file lives at `node_modules/@wordpress/theme/src/prebuilt/css/design-tokens.css` and is loaded by [src/main.jsx](../main.jsx). It exposes a semantic token set; the names you'll reach for most:

| Concern | Token examples |
|---|---|
| Backgrounds | `--wpds-color-bg-interactive-brand-strong`, `--wpds-color-bg-surface-neutral-weak`, `--wpds-color-bg-surface-info` |
| Foregrounds | `--wpds-color-fg-content-neutral`, `--wpds-color-fg-on-bg-interactive-brand-strong`, `--wpds-color-fg-content-success` |
| Strokes | `--wpds-color-stroke-surface-neutral`, `--wpds-color-stroke-focus` |
| Spacing | `--wpds-dimension-padding-xs`, `--wpds-dimension-gap-md`, `--wpds-dimension-margin-lg` |
| Radii | `--wpds-border-radius-sm`, `--wpds-border-radius-md`, `--wpds-border-radius-lg` |
| Border widths | `--wpds-border-width-xs`, `--wpds-border-width-md`, `--wpds-border-width-focus` |

The full set is autogenerated by Terrazzo upstream — open the file to see every value. The brand color today is `#3858e9`.

## 3. Which component to reach for

Always pick the WordPress package first. Author bespoke CSS only for layout glue (containers, grids, view-level chrome) and reference `--wpds-*` tokens — never raw hex or raw `px` for whitespace.

### From `@wordpress/ui` (the allowlist enforced by `@wordpress/use-recommended-components`)

| You need… | Use |
|---|---|
| Status pills / labels (e.g. "Draft", "Published") | `Badge` |
| Surface that groups related content | `Card.Root` + `Card.Content` (+ `Card.Header`, `Card.Title`, `Card.FullBleed`) |
| Expand/collapse section | `Collapsible` or `CollapsibleCard` |
| Zero state | `EmptyState` |
| External / inline link | `Link` (use `openInNewTab` for external) |
| Horizontal / vertical layout | `Stack` (props: `direction`, `gap` xs–3xl, `align`, `justify`, `wrap`) |
| Typography | `Text` (variants: `heading-2xl`/`xl`/`lg`/`md`/`sm`, `body-xl`/`lg`/`md`/`sm`) |
| Screen-reader-only text | `VisuallyHidden` |

### From `@wordpress/components`

Use the stable, non-experimental components first. The experimental (`__experimental*`) controls are still in use across Gutenberg and are acceptable here when no stable equivalent exists — but check the lint denylist below.

| You need… | Use |
|---|---|
| Button (icon-only or text) | `Button` (variants `primary`, `secondary`, `tertiary`, `link`) |
| Text/textarea/number/unit input | `TextControl`, `TextareaControl`, `__experimentalNumberControl`, `__experimentalUnitControl` |
| Select / radio / checkbox / toggle | `SelectControl`, `RadioControl`, `CheckboxControl`, `ToggleControl` |
| Range slider / box control | `RangeControl`, `__experimentalBoxControl` |
| Color / typography pickers | `ColorPicker`, `__experimentalColorPalette`, `FontSizePicker` |
| Tabs | `Tabs` |
| Toggle group (segmented) | `ToggleGroupControl` |
| Search input | `SearchControl` |
| Dropdown / dropdown menu | `Dropdown`, `DropdownMenu` |
| Modal / popover / tooltip | `Modal`, `Popover`, `Tooltip` |
| Sidebar panel sections | `PanelBody` |

### Denylist enforced by the lint rule

The `@wordpress/use-recommended-components` rule will error if you import any of these from `@wordpress/components`. Use the suggested alternative:

| Avoid (from `@wordpress/components`) | Use instead |
|---|---|
| `ExternalLink` | `Link` from `@wordpress/ui` (pass `openInNewTab`) |
| `VisuallyHidden` | `VisuallyHidden` from `@wordpress/ui` |
| `__experimentalHeading`, `__experimentalText` | `Text` from `@wordpress/ui` |
| `__experimentalHStack`, `__experimentalVStack` | `Stack` from `@wordpress/ui` |
| `__experimentalZStack` | Write CSS — slated for deprecation |
| `Card`, `CardBody`, `CardHeader`, `CardMedia` | `Card.Root` / `Card.Content` / `Card.Header` / `Card.FullBleed` from `@wordpress/ui` |
| `CardDivider`, `CardFooter` | Removed pattern — drop them |

The rule also restricts `@wordpress/ui` imports to the allowlist above. New components arrive there incrementally — track [gutenberg#76135](https://github.com/WordPress/gutenberg/issues/76135) for additions.

## 4. Forbidden patterns

- Raw hex colors. Use a `--wpds-color-*` token from `@wordpress/theme`.
- Raw `px` values for padding, margin, or gap. Use a `--wpds-dimension-*` token, or a `Stack` with a `gap` prop.
- Hand-rolling a button, text input, modal, popover, dropdown, or tabs. Reach for the WordPress package first.
- Importing items from the lint rule's denylist (see Section 3).
- Sass / Less / PostCSS-specific syntax. The repo is plain CSS.
- CSS-in-JS, Tailwind, styled-components.

## 5. Relationship to `src/styles/wordpress-vars.css`

The legacy `--wp-*` variables in [src/styles/wordpress-vars.css](../styles/wordpress-vars.css) predate `@wordpress/theme`. They are **still consumed** by existing chrome/views CSS, so the file stays in place — but **new CSS should reference `--wpds-*` tokens** from `@wordpress/theme/design-tokens.css`. Migration of legacy callers happens incrementally as features are touched.

## 6. Migration appendix (history)

[PR #9](https://github.com/getdave/rsm-editor-prototype/pull/9) introduced a hand-rolled `--wpds-*` token layer and five local primitives (`Button`, `TextControl`, `TextareaControl`, `Checkbox`, `Text`) under `src/design-system/primitives/`. Both have been removed in favor of the official `@wordpress/theme` / `@wordpress/ui` / `@wordpress/components` packages, which expose the same `--wpds-*` prefix with a richer, more semantic shape and are kept up to date upstream. There is no compatibility shim — any new caller imports from `@wordpress/*` directly.
